# EMARX 脚注工程化协议

本协议规定脚注从生成到交付的工程化标准。目标是每条脚注可追溯、可验证、格式统一，交付前通过闭环对账。引用贴句等论证层规则见 `citation-fact-protocol-v7.md`，本协议只管脚注本身的机械与著录质量。

## 一、一注一证

1. 一个脚注只著录一条文献。禁止用分号、"。又""另见"把多条文献塞进同一个注号。
2. 一句话最多一个脚注标记。一句话确需多条文献支撑时，拆成两句分别标注，不用 `[1][2][3]` 堆叠绕开。
3. 发现复合脚注必须拆分：原注号中的 N 条文献扩展为 N 个独立脚注，正文标记同步扩展，编号全局重排。

## 二、闭环对账

每次改动脚注后必须对账，三者一致才可宣称完成：

- Markdown 脚注定义数 == 正文引用标记数；
- 编号连续，无缺号、无重号；
- Word 交付稿脚注 XML 条目数 == Markdown 定义数。

对账数字必须写进交付报告（如"脚注 448/448，编号连续"）。任何一项不一致，只能说明正在回炉，不能宣称完成。

## 三、著录形态：首次完整 + 后续短引

1. 同一文献第一次引用：完整 GB/T 7714 著录。
2. 同一文献再次引用：改为短引（作者. 题名或书名主体, 年: 页码），不重复完整著录。
3. 禁止"参见""前引""同上""同前"等无法直接追溯的写法。所有短引必须让读者能定位到具体文献，不依赖上下文猜测。
4. 短引不得先于首次完整著录出现，按正文首次出现顺序核对。

## 四、语义归并与重复处理

1. 识别同一文献的著录变体：带日期/不带日期、全角/半角标点、有/无析出篇名、有/无"第X页"字样。**字符串不同不等于不同文献**，归并判断按"作者—作品—卷册—页码"的实际指向。
2. 同一段内、同一文献、同一页码的完全重复脚注可以合并。
3. 不同原句、不同页码、跨段落的引用必须保留独立脚注，不得为了减数合并——合并会让后一个原句失去就近出处。
4. 合并与删除只能由主模型逐组确认后执行，脚本只负责发现候选组，不得自动删除。

## 五、文集类原始文献的书级著录

对文集、全集、多卷本原始文献（如《马克思恩格斯全集》《列宁全集》《毛泽东文集》《习近平谈治国理政》及人物个人文集）：

- 脚注以文集/全集为著录主体，保留卷册和页码，不写析出单篇题名（除非单篇本身就是论证对象）；
- 格式示例：`马克思, 恩格斯. 马克思恩格斯全集: 第4卷[M]. 北京: 人民出版社, 1958: 488.`；
- 同一段连续引用同一册的多个页码，合并为一条脚注，页码按顺序列出；
- 出版年份按实际使用版本填写，不得照抄他人示例中的版本年份。

## 六、审计脚本

```bash
python scripts/footnote_audit.py --paper paper.md --output footnote-audit.json
```

检查项：

- 闭环对账（定义数/引用数/缺号/重号）；
- 复合脚注候选（一注多文献）；
- 禁用词（参见/前引/同上/同前/另见）；
- 著录变体重复组候选（同一文献的不同写法）；
- 同段同文献同页码的完全重复候选；
- 短引先于完整著录的顺序问题候选。

脚本输出只是候选清单，必须由主模型逐组人工确认后才可改动。脚本结论为 0 也不等于无问题——著录语义归并依赖规范化规则，变体超出规则覆盖时会漏报，交付前主模型应抽查。

## 七、失败信号

- 对账数字不一致却宣称完成；
- 用脚本自动批量合并脚注，不同原句的出处被覆盖；
- 脚注中出现"参见""前引文献"等模糊写法；
- 同一页上同一文献的完整著录重复出现；
- 文集引注写析出单篇题名，导致同一册文集被当成多条不同文献。
